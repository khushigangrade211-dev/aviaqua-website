# AviAqua — Business Management Application

Full-stack React + Express application for AviAqua. The frontend and API are served from the same Render web service.

## Persistent storage

Production uses PostgreSQL through the `pg` package. The existing application data model is stored as one JSONB document in the `aviaqua_app_store` table. This preserves the current API and business workflows while moving writes off the service filesystem. The table is created automatically at startup; `database/init.sql` is provided for reference. Writes are queued in order and flushed during graceful shutdown.

Local development can continue to use `data/aviaqua-db.json` when `DATABASE_URL` is not set. Production refuses to start without `DATABASE_URL`, `JWT_SECRET`, `ADMIN_PASSWORD`, and `CORS_ORIGIN`.

## Local development

1. Install Node.js 22.12+.
2. Run `npm install`.
3. Copy `.env.example` to `.env` and set a strong local `JWT_SECRET` and `ADMIN_PASSWORD`.
4. Run `npm run dev`.
5. Run `npm run build` to create the production frontend bundle.

## Deploy to Render

1. Push this project to a GitHub repository.
2. In Render, choose **New → Blueprint** and select the repository containing `render.yaml`.
3. Render creates the web service and PostgreSQL database described in the blueprint. `DATABASE_URL` is wired to the database's internal connection string, and `JWT_SECRET` is generated by Render.
4. In the web service's Environment settings, set:
   - `ADMIN_PASSWORD`: a unique, strong password for the first admin account. Do not use a sample/default password.
   - `CORS_ORIGIN`: your deployed site origin, e.g. `https://your-service-name.onrender.com` (no trailing slash). Add a comma-separated list only if you intentionally use more than one frontend origin.
   - Optional SMTP variables if email notifications are required.
5. Deploy. Check `https://YOUR-SERVICE.onrender.com/api/health` and confirm it reports a healthy status.
6. Test registration/login and submit a test enquiry. Restart/redeploy the service and verify that the enquiry remains present.

## Security notes

- Never commit `.env`, database URLs, passwords, or JWT secrets.
- Configure `ADMIN_PASSWORD` before the first production boot. The initial admin account is created using that password and bcrypt hashing.
- Sample employee/customer accounts are seeded with random undisclosed passwords, not shared demo credentials.
- Rotate any credentials that were previously committed to a public repository.
- Uploaded files currently use in-memory upload handling; if the application needs long-term file attachments, configure object storage rather than relying on the Render filesystem.
